# Phase 19 Security, REST Permission, Source, and Secret Exposure Review

Date: 2026-05-14

Linear issue: `ONE-125`

Status: In Review

## Scope

Reviewed the Phase 19 release-readiness security pass across:

- `bookings-flights-core` REST controllers, admin screens, settings, shortcodes, frontend routes, AI provider wiring, reports, cron/job paths, privacy handlers, and repositories.
- Active runtime REST routes under `baf/v1`, including routes contributed by the local affiliate bridge.
- Tracked official Travelpayouts plugin REST/AJAX surfaces that appear in the runtime route inventory.
- Active local affiliate bridge and content manager code paths for live-route exposure context; these plugins are currently untracked in this repository, so no files from those directories were added to this PR.
- Admin and public runtime source output with temporary fake secrets.

## Result

P19.6 passes locally for the PR candidate. No production-code patch was required. The pass found no app-owned REST route missing a real permission callback, no protected write action without a nonce/capability or explicit shared-secret gate, and no fake provider/API/postback secret in admin HTML, public frontend source, public config REST output, or the official Travelpayouts token REST response.

The runtime route inventory reported two missing permission callbacks on namespace index records:

- `/redux_travelpayouts/descriptors/v1`
- `/travelpayouts/widget`

Both are `WP_REST_Server::get_namespace_index` records generated by WordPress for namespace discovery, not custom app callbacks. All concrete Bookings and Flights, affiliate bridge, Redux Travelpayouts, and Travelpayouts widget action routes in the reviewed inventory had explicit permission callbacks.

## Security Review

Passed locally.

- `baf/v1/destinations`, `baf/v1/routes`, and `baf/v1/affiliate/click` remain intentionally public with explicit callbacks and bounded validation.
- `baf/v1/status`, `baf/v1/ai/itinerary`, `baf/v1/ai/handoff`, and `baf/v1/saved-trips` deny unauthenticated/protected access.
- Saved-trip and AI handoff write routes keep REST nonce requirements.
- Admin settings and widget placement writes keep capability checks and WordPress nonces.
- Alert signup/delete flows keep nonce, consent, validation, throttling, and signed delete-token boundaries.
- Fake Travelpayouts, AI, affiliate bridge, and postback secrets were absent from admin source, public source, public config output, and the Travelpayouts token route.
- AI provider errors and session logging still avoid storing or rendering raw prompts, bearer tokens, provider payloads, and provider keys.
- Travelpayouts markers/SubIDs remain public affiliate attribution identifiers, not private API credentials.

## Bugs Found

No production-code security bug was found in this gate.

Validation issues found and corrected during review:

- Initial REST smoke expected `/baf/v1/travel-deals`, but that route is not currently registered by `bookings-flights-core`; Phase 17 deal pages are template/CPT-driven, not exposed through a core REST collection route in this phase.
- Initial unauthenticated POST checks for protected endpoints omitted required request params and therefore hit REST argument validation before permission assertions; the follow-up supplied minimal params and confirmed `401` denial.
- Initial keyboard validation stayed inside the long WordPress admin menu; the follow-up used the skip link and reached protected integration controls.
- Initial browser request filtering treated a generic WordPress admin AJAX abort as app-owned; the final pass scoped request failures to Bookings and Flights routes/assets.

## Bugs Deferred

No P19.6 security blocker remains.
